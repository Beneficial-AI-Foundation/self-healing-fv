**`negate_hoare_spec`** (done):

> After the Aeneas/Lean update, `mvcgen [negate]; all_goals try simp` no longer leaves behind the five instance side goals that the old proof closed with `exact inferInstance`. Because of that, the first `exact inferInstance` landed on a real arithmetic goal, `↑r ≤ 36028797018963664`, and failed. I removed the five `· exact inferInstance` lines and kept the other case proofs unchanged; the file now compiles with no errors (the only `sorry` warnings come from the existing helper specs above the theorem, which I did not touch).

**`square2_spec`** (done):

> After the Aeneas/Lean update, the postcondition of `pow2k a 1` gives the exponent as `2 ^ 1` and no longer reduces it to `2`, so the final rewrite chain left the goal `2 * x ^ 2 ^ 1 % p = 2 * x ^ 2 % p`. I added `pow_one` to the existing `rw` chain, which closes the goal. The file builds successfully.

**`sub_spec`** (done):

> After the toolchain/Mathlib bump, `simp at final` on `asum + kjsum ≡ asum + 0 [MOD p]` now normalizes all the way to `p ∣ kjsum` (via a new/changed simp lemma for ModEq cancellation), so `exact final` mismatched the goal. Replaced `simp at final` with `rw [Nat.add_zero] at final`, which yields exactly the goal; the file builds cleanly.

**`double_spec'`** (done):

> The `Z ≠ 0` subgoal was closed by `grind`, which now fails because grind's ring solver rejects `ZMod p` (its `Inv` instance no longer matches `Field.toGrindField.toInv` up to reducible defeq). I replaced it with a direct proof: rewrite `(y·Z)² − (x·Z)²` as `Z² · (1 + d·x²·y²)` using the curve equation and `ring`, then apply `mul_ne_zero (pow_ne_zero 2 hZ_nonzero) h_denom_plus`.

**`add_spec`** (done):

> After the Aeneas update, the add_loop_spec postcondition sum_post_3 ends in `+ 2 ^ (52 * 0) * (0 / 2 ^ 52)` instead of a plain `+ 0`, so `simp only [add_zero] at sum_post_3` made no progress. I changed that one line to `simp only [Nat.zero_div, mul_zero, add_zero] at sum_post_3`; the rest of the proof is unchanged and Add.lean builds with no errors. Caveat: the build warns that sub_spec in Sub.lean:86 (which add_spec uses) still contains `sorry`, so add_spec is only fully proved once that is gone.

**`montgomery_mul_hoare_spec`** (done):

> After the Aeneas/Lean update, `mvcgen [montgomery_mul]` leaves only the final modular-equivalence goal; the two side goals the old proof closed with `grind` no longer appear, so the first `grind` hit the final goal and failed. I replaced the tactics after mvcgen with `rename_i h _; intro h1; rw [Nat.ModEq, ← h, h1]`, which closes the goal directly; the file builds successfully.
